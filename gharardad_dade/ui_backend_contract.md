# قرارداد داده‌ای و رابط تعاملی فرانت‌اند با بک‌اند (UI <-> Backend Contract)
### پروژه: دستیار هوشمند اسناد PDF فارسی (RAG آفلاین)
### طرفین قرارداد: زینب (موتور بازیابی و پایگاه داده برداری) و مشکات (رابط کاربری و ماژول پاسخ)

---

## ۱. هدف و فلسفه این سند

این سند مکمل قرارداد داده‌ای قبلی (`data_contract.md` مربوط به فاطمه) است و نقطه اتصال فرانت‌اند (مشکات در `ui.py`) با لایه‌های بک‌اند (زینب و فاطمه) را تعریف می‌کند.

اهداف اصلی این قرارداد:
1. **تعریف صریح توابع ایجاد و حذف چت و فایل** در پایگاه داده برداری (`vector_db.py`).
2. **پشتیبانی از افزودن فایل در هر زمان** (ابتدای چت یا در میانه گفتگو).
3. **مدیریت وضعیت پیشرفت سیستم (System Status)** و رفتار رابط کاربری هنگام پردازش اسناد.
4. **تعریف گارد و پیام بازدارنده چت** در زمان پردازش فایل‌ها.
5. **تثبیت امضاها و نوع داده‌های ورودی/خروجی** برای ارکستراتور تولید پاسخ به صورت استریم.

---

## ۲. توابع مدیریت چت و اسناد در پایگاه برداری (`vector_db.py`)

مشکات از طریق نمونه کلاس `VectorDB` با پایگاه برداری کار می‌کند:

```python
from vector_db import VectorDB

vdb = VectorDB()
```

### ۲.۱. ایجاد گفتگوی جدید (`create_chat`)
هنگامی که کاربر در صفحه اصلی روی «گفتگوی جدید» کلیک می‌کند:
* **متد:** `vdb.get_or_create_collection(chat_id: Union[int, str])`
* **ورودی:** `chat_id` (شناسه چت تولیدشده در دیتابیس)
* **عملکرد:** ساخت یک کالکشن اختصاصی و ایزوله در ChromaDB به نام `chat_{chat_id}` با متریک فاصله کسینوسی.
* **موقعیت فراخوانی در UI:** در تابع `save` داخل دیالوگ ایجاد چت در `ui.py`.

---

### ۲.۲. افزودن فایل به چت (`add_file_to_chat`) — در ابتدا یا میانه گفتگو
کاربر می‌تواند در **ابتدای ساخت گفتگو** یا **در میانه گفتگو (بعد از چند پرسش و پاسخ)** فایل جدیدی به منابع اضافه کند. همچنین کاربر آزاد است قبل از پرسیدن هرگونه سوالی، چند فایل را پشت سر هم اضافه یا حذف کند.

* **تابع پایپ‌لاین:**
```python
async def process_document_pipeline(
    file_path: str,
    chat_id: int,
    doc_id: str,
    on_progress: Optional[Callable[[str, float], None]] = None
) -> bool:
```
* **ورودی‌ها:**
  * `file_path`: مسیر ذخیره فایل روی دیسک (در پوشه `uploaded_files/`).
  * `chat_id`: شناسه گفتگوی فعال.
  * `doc_id`: شناسه یکتای سند در چت (مثلاً `chat{chat_id}_{file_name}`).
  * `on_progress`: تابع کال‌بک برای دریافت پیام‌های مرحله‌ای وضعیت.
* **نکته بسیار مهم فنی (Incremental Ingestion):**
  هنگام افزودن فایل جدید به یک چت موجود، چانک‌های فایل جدید بدون آسیب دیدن تاریخچه چت یا چانک‌های فایل‌های قبلی، به کالکشن اضافه (`upsert`) می‌شوند.

---

### ۲.۳. حذف فایل از گفتگو (`delete_file`)
هنگامی که کاربر روی آیکون سطل زباله کنار یک سند کلیک می‌کند:
* **متد:** `vdb.delete_file_chunks(chat_id: Union[int, str], doc_id: Union[int, str]) -> bool`
* **ورودی:** `chat_id` و `doc_id`.
* **عملکرد:** تمام چانک‌های وکتور مربوط به آن سند خاص از ChromaDB حذف می‌شوند.
* **موقعیت فراخوانی در UI:** در تابع `delete_f` در پنل اسناد `ui.py`.

---

### ۲.۴. حذف کامل گفتگو (`delete_chat`)
هنگامی که کاربر یک گفتگو را به طور کامل حذف می‌کند:
* **متد:** `vdb.delete_chat_collection(chat_id: Union[int, str]) -> bool`
* **ورودی:** `chat_id`.
* **عملکرد:** کالکشن اختصاصی آن چت به طور کامل از دیسک پاک می‌شود.
* **موقعیت فراخوانی در UI:** در تابع `do_delete` دیالوگ حذف در صفحه گالری گفتگوها.

---

## ۳. مدیریت وضعیت سیستم و رفتار بازدارنده چت (Status Guard)

### ۳.۱. مراحل استاندارد گزارش وضعیت به کاربر
بک‌اند در طول پردازش هر سند، تابع کال‌بک `on_progress(message, progress)` را فراخوانی کرده و وضعیت را چند بار به‌روزرسانی می‌کند:

| مرحله | پیشرفت (`progress`) | پیام نمایشی در رابط کاربری (`message`) | مسئول |
| :---: | :---: | :--- | :---: |
| ۱ | `0.10` | `"در حال خواندن فایل PDF..."` | فاطمه |
| ۲ | `0.30` | `"استخراج متن و پاکسازی صفحات..."` | فاطمه |
| ۳ | `0.55` | `"قطعه‌بندی معنایی متن سند (چانک‌بندی)..."` | فاطمه |
| ۴ | `0.80` | `"تولید بردارها با مدل هوش مصنوعی..."` | زینب |
| ۵ | `0.95` | `"نمایه‌سازی در پایگاه داده برداری..."` | زینب |
| ۶ | `1.00` | `"تکمیل پردازش اسناد"` | سیستم |

> **علامت پایان:** رسیدن وضعیت به عبارت دقیق **`"تکمیل پردازش اسناد"`** یا مقدار پیشرفت `1.00` به معنی اتمام تمام مراحل است.

---

### ۳.۲. قانون بازدارنده در رابط کاربری (In-Flight Processing Guard)

* **سناریو:** اگر فرآیند پردازش سندی در جریان باشد (یعنی پیام هنوز به «تکمیل پردازش اسناد» نرسیده است) و کاربر در کادر چت سوالی بپرسد:
* **رفتار الزامی UI:**
  رابط کاربری نباید درخواست را به مدل زبانی ارسال کند؛ بلکه بلافاصله پیام آماده زیر را به عنوان پاسخ دستیار نمایش می‌دهد:
  ```text
  ⚠️ در حال پردازش اسناد .... لطفاً منتظر بمانید
  ```
* **پیاده‌سازی در `ui.py`:**
  مشکات یک فلگ برای وضعیت چت یا وضعیت اسناد نگه می‌دارد (مثلاً `is_processing_docs`):
  ```python
  if is_processing_docs:
      # عدم ارسال به RAG و نمایش پیام آماده بازدارنده
      db.add_message(chat_id, role='assistant', content='⚠️ در حال پردازش اسناد .... لطفاً منتظر بمانید')
      render_messages()
      return
  ```

## ۴. تابع تولید پاسخ کاربر (Orchestrator / Answer Generator)

پس از اتمام پردازش اسناد، سوالات کاربر از طریق این تابع پردازش می‌شوند:

### ۴.۱. امضای تابع
```python
from typing import AsyncGenerator, Dict, Any, List, Optional

async def get_rag_response_stream(
    query: str,
    chat_id: int,
    filter_doc_ids: Optional[List[str]] = None
) -> AsyncGenerator[Dict[str, Any], None]:
    ...
```

### ۴.۲. ورودی‌ها (Inputs)
* `query (str)`: متن سوال کاربر.
* `chat_id (int)`: شناسه گفتگوی فعال.
* `filter_doc_ids (Optional[List[str]])`: لیست اختیاری از شناسه اسنادی که کاربر انتخاب کرده است؛ در صورت عدم انتخاب، مقدار `None` پاس داده می‌شود تا در تمام اسناد چت جستجو شود.

### ۴.۳. ساختار خروجی استریم (Yields)
1. **توکن‌های متنی زنده:**
   ```json
   { "type": "token", "content": "کلمه " }
   ```
2. **استنادها و مراجع در انتهای پاسخ:**
   ```json
   {
     "type": "sources",
     "citations": [
       {
         "doc_id": "doc_0001",
         "filename": "sample.pdf",
         "page_number": 4,
         "score": 0.89,
         "snippet": "بخشی از متن استخراج‌شده..."
       }
     ]
   }
   ```

## ۵. ماتریس تعهدات تیمی (Checklist)

| بخش | مسئول | وظیفه دقیق |
| :--- | :---: | :--- |
| **ایجاد چت و فایل** | **مشکات** | فراخوانی `vdb.get_or_create_collection` هنگام ساخت چت و فراخوانی `process_document_pipeline` هنگام آپلود فایل. |
| **حذف چت و فایل** | **مشکات** | فراخوانی `vdb.delete_file_chunks` و `vdb.delete_chat_collection` در رویدادهای حذف. |
| **قفل پردازش چت** | **مشکات** | بررسی وضعیت اسناد و ارسال پیام آماده `"در حال پردازش اسناد .... لطفاً منتظر بمانید"` در صورت ناتمام بودن پردازش. |
| **پردازش متن PDF** | **فاطمه** | استخراج متن، تمیزکاری و چانک‌بندی با ارسال وضعیت به کال‌بک در هر مرحله. |
| **پایگاه داده و ارکستراتور** | **زینب** | ذخیره چانک‌ها در `VectorDB`، اجرای جستجو با `retriever` و ارائه خروجی استریم توکن + مراجع. |
